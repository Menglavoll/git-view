# Feature Specification: 远程仓库批量创建 Tag

**Feature Branch**: `004-batch-create-tags`

**Created**: 2026-09-06

**Status**: Draft

**Input**: 在远程仓库页面选择目录或项目，批量为多个远程项目按指定分支创建轻量或附注 Tag。

## 背景

当前远程仓库页面已经提供树形目录、目录级联选择、批量操作弹窗和远程分支查询能力，但 Provider 尚未提供创建 Tag 的统一抽象。本特性在不改变现有三平台账号与远程仓库模型的前提下，增加一次批量配置、预检查、确认、执行和结果查看闭环。

## 用户故事

### US1 - 从目录选择项目并打开批量 Tag 页面（P1）

用户在远程仓库树形视图中勾选一个目录，系统选中该目录下全部项目；用户可以取消部分项目，然后点击“批量添加 Tag”进入批量配置页面。

列表视图仍支持逐项目多选。批量页面还可以清除筛选后从当前远程仓库列表继续添加项目，也可以移除已选项目。

### US2 - 配置每个项目的分支与 Tag（P1）

批量配置页面逐行展示项目、所属平台、所属账号、目标分支、分支最新提交和 Tag 配置。每个项目默认使用自己的默认分支和轻量 Tag，用户可独立修改。

Tag 类型支持：

- 轻量 Tag：不需要说明；
- 附注 Tag：必须填写 1～2000 个字符的多行说明，创建者使用远程账号的平台身份。

统一 Tag 名称用于初始化所有项目，之后允许单独修改某些项目的名称。不同项目允许使用相同 Tag 名称。

### US3 - 预检查、摘要确认与执行（P1）

用户点击“创建”后，系统执行预检查。预检查失败的项目必须明确列出，用户只能修正或移除失败项目，不能跳过失败项目创建其他项目。所有项目通过后，系统展示确认摘要，摘要包含预检查时的分支 SHA，用户确认后才真正创建 Tag。

创建时按执行瞬间读取到的分支最新提交创建。若与预检查 SHA 不同，在结果中提示分支发生变化。

### US4 - 查看结果并重试失败项目（P1）

批量执行按项目隔离。成功项目保留，失败项目展示明确原因，取消的剩余项目标记为取消。用户可以一键重试失败项目；重试必须重新读取分支、重新预检查并再次经过确认窗口。

## 功能需求

- **FR-001**: 树形视图 MUST 支持勾选平台或命名空间目录并级联选中其全部子项目。
- **FR-002**: 用户 MUST 可以在批量页面移除项目，并可以清除筛选后继续添加当前远程仓库列表中的项目。
- **FR-003**: 列表视图 MUST 支持逐项目多选；切换视图、筛选或刷新导致项目集合变化时，系统 MUST 清理失效选择。
- **FR-004**: 批量页面 MUST 展示每个选中项目的项目名、平台和账号。
- **FR-005**: 每个项目 MUST 独立选择已存在的远程分支，默认选择该项目的默认分支；不允许提交不存在的手动输入分支。
- **FR-006**: 分支选择 MUST 支持关键字筛选；分支下拉可采用惰性加载，并在本次批量会话中缓存已加载结果。
- **FR-007**: 选定分支后 MUST 展示该分支最新提交的短 SHA 和提交描述首行；完整 SHA 通过 tooltip 或详情展示。
- **FR-008**: Tag 类型默认 MUST 为轻量 Tag，且 MUST 允许逐项目切换为附注 Tag。
- **FR-009**: 附注 Tag 说明 MUST 逐项目独立编辑，不能为空，长度 MUST 为 1～2000 个字符，并支持多行文本。
- **FR-010**: 系统 MUST 使用对应远程账号的平台身份作为 Tag 创建者；首版不支持 GPG/SSH 签名 Tag。
- **FR-011**: 系统 MUST 支持统一 Tag 名称初始化所有项目，并允许逐项目修改；不同项目可以使用相同名称。
- **FR-012**: 同一远程项目中已存在目标 Tag 时 MUST 禁止覆盖，不提供强制覆盖选项。
- **FR-013**: Tag 名称 MUST 按 Git ref 合法性校验，不限制版本号格式。至少禁止空名称、`.`、`..`、空格、控制字符、首尾 `/`、连续 `..`、`.lock` 结尾和 `@{`。
- **FR-014**: 创建前 MUST 对项目、账号权限、分支、分支提交、Tag 合法性、Tag 是否已存在及附注说明执行预检查。
- **FR-015**: 预检查失败项目 MUST 显式列出；存在失败项目时创建按钮 MUST 不可用，用户必须修正或移除失败项目。
- **FR-016**: 确认摘要 MUST 展示每个项目的平台、账号、分支、预检查 SHA、Tag 类型、Tag 名称和附注说明摘要。
- **FR-017**: 用户未在确认窗口点击确认前，系统 MUST NOT 调用创建 Tag 的写接口。
- **FR-018**: 执行时 MUST 以当时读取到的分支最新提交为准；如果 SHA 与预检查不同，结果 MUST 提示变化。
- **FR-019**: 并发数默认 MUST 为 3，用户可设置 1～20 的整数；批量项目总数不设上限。
- **FR-020**: 用户取消时 MUST 仅取消尚未发送的项目；已经发送到远程平台的请求无法撤销。
- **FR-021**: 批量执行 MUST 支持部分成功、部分失败，单个项目失败不得阻断其他项目。
- **FR-022**: 结果页面 MUST 支持一键重试失败项目；重试必须重新预检查和确认。
- **FR-023**: 未完成批量任务 MUST NOT 在应用重启后恢复。
- **FR-024**: 操作日志 MUST 记录批量摘要和每个项目的项目名、分支、Tag 名称、状态、错误原因和耗时。
- **FR-025**: 如果目标平台不支持所选 Tag 类型，项目 MUST 在预检查阶段失败，不得自动降级为另一种 Tag 类型。

## 非功能需求

- 批量任务执行应使用后端统一调度，不由前端并发发起多个不受控的写请求。
- Token、密码和带凭据 URL 不得出现在 UI、错误、日志或返回模型中。
- 网络失败、权限不足、限流、项目不存在和 Tag 冲突必须转换为可理解的中文错误。
- 批量页面中项目总数较大时仍应保持可滚动和可操作；并发只允许 1～20。
- 复用现有 Vue、Element Plus、Pinia、Tauri command、Provider 和操作日志架构，不引入新的第三方依赖。

## 不在范围内

- Tag 列表查询；
- Tag 修改、删除或覆盖；
- 跨平台分布式事务和自动回滚；
- 应用重启后恢复批量任务；
- GPG/SSH 签名 Tag；
- Tag Release、Release 说明和附件管理。

## 验收标准

- 目录勾选、单项目取消、批量页面增删项目均正确工作。
- 每个项目可以选择不同分支，并看到分支最新短 SHA 和提交描述。
- 同一批次中可以混合轻量 Tag 和附注 Tag；附注说明逐项目校验。
- 预检查失败项目会阻止创建，并可修正或移除。
- 确认摘要包含预检查 SHA，最终创建使用执行时最新 SHA。
- 最大并发为 20，默认并发为 3，批量项目总数不限。
- 成功、失败、取消和重试结果清晰可见，且日志完整脱敏。
